继续减少首次安装、重新打开和后台返回时的等待。

- 首次准备运行包最多同时下载 3 个分片，使用统一进度；保留断点续传和已验证的下载缓存。下载失败先换来源，后续分块和分片优先沿用可用来源，减少反复等待失效来源的时间。
- 同一 Service 中已经完成准备的存活内核可以直接连接，减少重复磁盘摘要和额外 HTTP 探测。证明绑定具体进程及环境指纹，替换、退出或环境变化时失效；冷启仍核对安装回执、运行包及可信清单，并减少重复组件校验。
- 首页交接或返回前台后，页面优先恢复。工具能力检查、更新检查及缓存安装包解析/清理延后到至少 5 秒无操作且任务已确认空闲时运行；触摸/按键、后台和重启撤销可选检查。空闲组件复核只读，发现问题在下次完整准备修复。
- 恢复错误监听不再随每次页面变化和固定轮询读取整页文字；改为合并处理有界的变化节点，隐藏时暂停，降低长对话及前后台切换时的页面开销。报告只使用固定错误标记。

沿用原签名、包名、payload-v14 和首页鲸鱼动画，可直接覆盖安装。所有分片的大小及 SHA-256 验证完成后才改动运行目录，保留原有快照和回滚；页面仍须真实连接和首帧就绪后才能交接。

本地完整 JVM、JS、Python 回归通过，包含 11 项分片并行/缓存/损坏取消检查、10 项真实 HTTP 下载检查、15 项生产启动路径和认证 RPC 检查、49 项生产自检调度与真实 Node 取消检查，以及页面监听的变化合并、隐藏暂停和扫描上限检查。完整 Android 构建及正式发布结果以 Actions 和发布清单为准。本轮没有手机或模拟器测速，实际首次安装、冷启、后台返回的耗时和体验由用户安装验收，不以桌面逻辑测试推算提速秒数。
