# 0.34.1：修复内核运行包清单大小限制

<!-- dsh-doc-status:start -->
> 版本记录：标题版本对应本次发布，原始变更内容保留，不覆盖为新版说明。 已发布 stable：**0.35.1**；源码：**0.36.0**；源码运行包：`payload-v13`；固定 DSH：`0.2.1-rc.3`（上游候选版）。[统一进度与验证边界](../docs/STATUS.md)。
<!-- dsh-doc-status:end -->

- 修复 0.34.0 更新内核时的“文件大小异常”：payload-v13 的完整清单为 302,511 字节，包含旧依赖删除清单，超过了旧的 256 KiB 接收上限。
- 清单接收上限调整为有界的 1 MiB；APK 内置 SHA-256、分片大小、目标目录、哨兵和删除路径校验继续生效。
- 使用真实发布清单新增检查，并放进完整构建和运行包消费流程，在打包、发布前验证 App 能接受其引用的清单。
- 沿用 payload-v13 / DSH 0.2.1-rc.3，无需重发或替换已发布运行包。保留原签名，覆盖安装后重试内核更新。
- 本轮不运行真机验证，用户自行下载安装调试。

## English

Fixes the runtime manifest rejection introduced in 0.34.0: payload-v13's 302,511-byte manifest exceeded the legacy 256 KiB limit. The bounded cap is now 1 MiB; pinned SHA-256 and structural/path checks remain enforced. CI now checks the actual published manifest against the App's admission rules before building and consuming the runtime. Uses the same payload-v13 and signing certificate.
