## v0.25.0 —— 深色模式（配色取自 DSH 网页自己的深色值）

系统切到深色后，原生界面（设置、文件浏览、日志、插件、余额、网络诊断）
现在会跟着变深色，不再是一屏刺眼白卡片。

### 配色不是我挑的，是从上游提取的

从 DSH 网页前端的主题包 `dsh-client-ui-theme` 里逐条解析
`body[data-ds-dark-theme]` 令牌，取的就是它自己的值：

| 用途 | 浅色 | 深色 |
|---|---|---|
| 页面底色 | `#F7F8FA` | `#151517` |
| 卡片 | `#FFFFFF` | `#232324` |
| 描边 | `#0000000a` | `#ffffff0f` |
| 输入框底 | `#F5F6F8` | `#2C2C2E` |
| 主 / 次 / 弱文字 | `#1F2329` / `#6B7280` / `#9CA3AF` | `#F9FAFB` / `#CFD3D6` / `#ADB2B8` |

### 一件必须做的事：让网页也知道天黑了

WebView 上报给网页的 `prefers-color-scheme` 跟随 **Activity 主题**。
如果只改原生配色、主题仍固定为浅色，网页会一直以为自己在浅色环境 ——
结果是「原生深色对话框 + 网页满屏白」的同屏割裂，比不做深色更难看。

所以新增了夜间主题资源：父主题换成非 Light 版本，网页才会跟着切到
DSH 自己的深色方案。同一处还解决了启动瞬间的白闪 ——
窗口底色在界面代码跑起来之前就已生效。

### 技术上的一个坑

颜色原本是 `public static final int` 编译期常量，javac 会把值**内联**到
每一处调用点 —— 也就是说运行时改这个常量，对已编译代码完全无效。
因此把它们全部改成方法，全仓库 65 处调用点跟着转换。

### 已知未做

  上游对应令牌已查到，下一版换。
* 系统 Toast、输入框光标与选择柄来自固定 Light 主题，未处理。
