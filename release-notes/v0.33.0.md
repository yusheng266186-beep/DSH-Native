## 本版生效（装上即得）

**导入凭据时被注释掉的同名键会静默跳过。** 原判定用
`indexOf(key + ":")`，于是凭据文件里 `# DEEPSEEK_API_KEY: ...`
这样一行会被当成「已配置」，导入被跳过而界面仍报告成功 —— 用户的密钥
其实从没写进去。现改为整行匹配并跳过注释行。

此外本版重构了 6 个高风险逻辑到可离线测试的纯逻辑类（运行包清单校验、
凭据导入、外链识别、YAML 顶层块、运行目录删除守卫、模型图片能力判定），
并让此前**从未被 CI 调用**的构建期闸门真正接入每次构建。

## 已修复但**需下一版运行包**才生效

**交互式终端在真机上一直无法使用。** 启动自检每次都报
`[错误] node-pty → Cannot find module './prebuilds/android-arm64/pty.node'`，
而那个文件其实就躺在运行包里。

根因不是文件缺失：运行包构建脚本把 **Termux 编译**的 `node-pty` 预编译
同时放进了 `linux-arm64` 与 `android-arm64` 两个槽位。它是正确的 AArch64
ELF，原有的魔数与架构断言全部通过，但它链接
`libutil.so.1` / `libstdc++.so.6` / `ld-linux-aarch64.so.1` —— 普通 Android
应用里一个都没有，`dlopen` 必然失败。node-pty 的加载器依次尝试多个路径且
只抛出最后一个错误，于是日志谎报「文件不存在」，真实原因被完全掩盖。

改用 `@mmmbuto/node-pty-android-arm64`（一直随包发布，只是从未被引用），
并在构建期解析 ELF 的 `DT_NEEDED`，拒绝任何链接 `libutil.so` 的二进制。


## 运行包瘦身（同样需下一版运行包才生效）

排除清单原先写死平台名，而构建环境已换成 x86_64 runner，装进来的是
`-linux-x64`，**清单完全失效**，死重一直混在包里。现改为按 ELF 事实判定
（不是 AArch64，或链接了只有桌面/Termux 才有的库）：

| 删除 | 解压后体积 |
|---|---|
| `sherpa-onnx-linux-x64`（语音转写，x86_64） | 32 MB |
| `node-pty` 的 Windows 预编译 | 23 MB |
| `koffi` / `node-addon-system` 等其他平台原生库 | ~4 MB |

实测压缩后减少约 14.5 MB。

## 构建期闸门首次真正生效

`check_java.py`（语法解析、跨类引用核验、三道构建闸门）**此前从未被 CI
调用过**，只在本机手动运行。现已接入每次构建。

同时锁定静默捕获（`catch (Throwable ignored)`）的上限：新增一处即构建失败，
逼着作者当场判断这里该不该记日志。现存 121 处里绝大多数是合理的清理，
不强行清零，只保证不再增长。

## 测试

新增 4 个离线测试类，共 140 条断言，覆盖此前零覆盖的安全相关逻辑：
运行包清单校验（路径逃逸、分片目标白名单、体积上限）、凭据导入、
外链识别、YAML 顶层块合并。纯逻辑类 44 → 46。

## 兼容性与边界

包名、签名、`minSdk 24` / `targetSdk 28`、数据目录与会话格式均不变，
支持直接覆盖安装，不调用付费模型。

需要说明的两点，关系到「装上就能用」的预期：

- **本版不包含终端修复与运行包瘦身。** APK 里固定了运行包的地址与清单摘要，
  两者都随发布确定。本次只发布 APK，因此终端仍需等运行包重建后的下一版；
  体积也不会变小。装上 0.33.0 的用户，交互式终端和 0.32.3 一样不可用 ——
  这是已知问题，不是新引入的。
- 终端修复已在真机验证（`dlopen` 三方对照 + 真实 PTY spawn 成功 + 完整
  `patch_android` 集成跑通），但**修复本身尚未随运行包下发**；本版 APK 也
  尚未经过完整的真机覆盖安装验收。

本版实际交付的是：凭据导入缺陷修复，以及一批重构与构建期防护
（详见上文「测试」「构建期闸门」两节）——这些都在 APK 内，装上即生效。
