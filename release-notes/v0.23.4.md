## v0.23.4 —— 状态栏不再误报「空闲」，页面不再自己刷新闪烁

这一版修的是两个你直接反馈的问题，根因都不是"显示错"，而是**证据本身错了**。

### 1. 任务在跑，通知栏却显示「空闲」

通知栏的运行状态原来是这样判断的：在网页控制台的一行文本里数
`"running":true` 出现了几次。但那一行是被**截断到 700 字符**的 ——
而 DSH 的会话列表里，一条会话的开头（sessionId / 时间 / cwd / token 用量…）
就足以吃满 700 字符。

结果是：**正在跑的那个会话只要不是列表里的第一项，它的 `"running":true`
就被截掉了**，数出来是 0，于是被判成「空闲」。而「数不到 = 空闲」这个
推断本身也是错的 —— 读不到证据不等于没有在跑。

现在改成：
- 由页面在**截断之前**解析完整 JSON，只上报一个数字（有几个会话在跑）；
- 另外把界面上的按钮（停止生成 / 发送消息 / 等待审批）作为**第二个独立证据源**；
- 两个来源合成时遵守一条规则：**任何一方说在跑就是在跑**；「空闲」必须有明确证据；
  两个来源都没有新鲜消息时，**保持原状态，不猜、也不降级成空闲**。

### 2. 窗口自己刷新/闪烁，而任务其实一直正常

自动刷新本来是为了救「页面断了连不上」。但它自己制造了循环：
刷新页面会**主动拆掉**正在重连的 WebSocket，DSH 立刻打印 connection lost，
看门狗又把它当成新故障 —— 15 秒后再刷一次。你的日志里实测到 **13 次**连续自动刷新。

现在三处一起改：
- 我们**自己触发的刷新**在 30 秒内引起的断连事件一律忽略（不再自己吓自己）；
- **任务正在运行时绝不刷新** —— 刷新会丢掉滚动位置和输入内容，而 agent 在后台照常干活，
  这正是你看到的"窗口重启但任务没停"；
- 连续自动刷新上限 2 次，之后停手并写日志，不再让界面一遍遍闪。

### 3. 顺带修掉的一个放大器

页面注入（状态采集、任务完成通知、接口错误诊断）原来**只在第一次加载时做一次**。
而任何一次刷新都会清空页面里的注入脚本，App 却以为"已经装好了" ——
于是刷新之后这些功能**全部静默失效**，通知栏永远停在刷新前的那一刻。
这就是上面两个问题的共同放大器，现在改成每次加载都注入。

### 4. 其他

- 状态推送失败时不再被空 catch 吞掉（此前推送失败会让通知栏永久停在旧状态，
  而用户正是据此判断 agent 还在不在干活）。
- 构建脚本：修复 `release.sh` 里一个会把 README 的 SHA-256 静默清空的变量名错误；
  `build_bootstrap.sh` 支持 `DSH_BUILD_DIR`（文档一直在写但脚本没读）；
  版本号脚本不再写死路径。
- **新增 CI 构建**（此前仓库里没有 `.github/`）：476 项断言与三道构建期闸门
  现在每个提交都会跑。

安装：直接在本 App 的通知栏 →「设置」→「检查 App 更新并安装」。
