## v0.23.6 —— 收尾：三个"静默失败"和两处小毛病

这一版把之前点名的几项一次做完。它们有个共同点：**出错时不吭声** ——
不崩溃、不报错，就是悄悄不工作，用户拿不到任何信息。

### 1. 从别的 App 分享进来的文件会丢（修好）

冷启动时分享文件进来，必然弹一句「工作区不可用，无法接收分享内容」，
文件直接丢掉；只有 App 已经在后台时才能成功 —— 所以表现为"时好时坏"。

原因：处理分享需要知道"工作区在哪"，而这个信息要等启动流程跑到中间才有值，
但处理分享的代码被放在了**启动之前**。现在改成先记下来，等工作区确定后再处理；
万一共享存储真的不可用，兜底落到应用私有目录，而不是把文件丢掉。
顺便把文件拷贝移到后台线程（分享几百 MB 的视频不会再卡住界面）。

### 2. 启动失败时，画面永远停在「正在启动…」，没有任何出路（修好）

两处叠加：

* 状态页只允许画一次 —— 第一次写的是「正在启动 DSH …」，顺手把更新通道锁死，
  之后所有「启动失败 / 已等待 N 秒 / 启动超时」全被丢掉，页面永远停在第一句；
* 该页面还被开屏盖着，而开屏只在启动流程跑到后段才收起。

现在允许覆盖更新，并且失败时给出明确出路：**一句话原因 + 「重试启动」链接 +
提示去通知栏更新运行包**，8 秒后自动露出说明页（不用用户去猜"要点一下"）。

### 3. Node 自检失败 → 永久白屏，点哪儿都没反应（修好）

这条自检决定整个架构立不立得住（Android 10+ 默认禁止执行私有目录里的文件，
本项目靠 targetSdk=28 绕开）。它失败时原来是**静默 return**，
而"把失败告诉用户"的代码全写在"抛异常"那条分支里 —— 于是开屏一直转圈、
屏幕不可点、看不到任何原因。

现在启动流程统一返回失败原因，**所有失败路径走同一个出口**。

### 4. 缓存安装包复用前会校验签名（新增）

更新逻辑有个"本地已有最新包就直接装、不重复下载"的优化，但它**只看版本号**。
同一个版本号重发（例如换签名后重发）时，缓存里那个装不上的包会被反复复用，
用户每次点更新都失败，而日志只说「使用已下载的 X 安装包」。
现在复用前会校验签名与已安装版本一致，不一致就删掉重新下载。

### 5. 两处小毛病

* 状态诊断日志在没收到数据时会打成 `（从未s 前）`，应为 `（从未收到）`；
* 启动流程加了互斥：启动没走完时再点「重试启动」不会并发跑两个启动。

### 另外

* 清掉了源码里两处 emoji（`PluginSpecs.java`、`bump_version.sh`）——
  `AGENTS.md` 把"源码不含 emoji"列为红线并称"构建脚本里有检查"，
  但实际上**那个检查从未存在**，所以一直没被拦住。红线目前仍只靠自觉。
* 启动失败的三条路径（抛异常 / 自检不通过 / 服务超时）现在共用一份代码，
  以后新增失败点只要返回原因即可自动获得同样的提示。

安装：通知栏 →「设置」→「检查 App 更新并安装」。
