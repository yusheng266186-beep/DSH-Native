## 本版重点：交互式终端终于可用，运行包体积大减

上一版（0.33.0）修的终端缺陷与瘦身都在**运行包**里，那次只发布了 APK，
所以并未生效。本版引用已发布的 payload-v11，两项一起交付。

### 交互式终端

此前每次启动自检都会报：

```
[错误] node-pty → Cannot find module './prebuilds/android-arm64/pty.node'
```

而那个文件其实就躺在运行包里。根因不是文件缺失：运行包构建脚本把
**Termux 编译**的 node-pty 预编译同时放进了 `linux-arm64` 与 `android-arm64`
两个槽位。它是正确的 AArch64 ELF，原有架构断言全部通过，但它链接
`libutil.so.1` / `libstdc++.so.6` / `ld-linux-aarch64.so.1` —— 普通 Android
应用里一个都没有，`dlopen` 必然失败。node-pty 的加载器依次尝试多个路径且
只抛出最后一个错误，于是日志谎报「文件不存在」，真实原因被完全掩盖。

现改用 Android/bionic 原生编译的 `@mmmbuto/node-pty-android-arm64`，并在构建期
解析 ELF 的 `DT_NEEDED`，拒绝任何链接 Termux 专有库的二进制。

### 运行包瘦身

排除清单原先写死平台名，而构建环境为 x86_64，装进来的是 `-linux-x64`，
清单完全失效，死重一直混在包里。现按 ELF 事实判定：不是 AArch64、或链接了
只有桌面/Termux 才有的库，一律剪除（本次剪掉 5 个目录，含 32 MB 在 arm64 上
永远无法加载的 x86_64 语音转写库，与 23 MB Windows 预编译）。

| dsh 分片 | 之前 | 现在 |
|---|---|---|
| 压缩 | 83.7 MB | **28.5 MB** |
| 解压 | 491 MB | **282 MB** |

四个工具分片字节复用未变。

## 验证

从实际产出的分片中解出 `node-pty/prebuilds/android-arm64/pty.node` 核对：
摘要与 Android 原生构建一致，`DT_NEEDED` 仅
`libc.so` / `liblog.so` / `libc++_shared.so` / `libdl.so` / `libm.so`，
`dlopen` 成功并导出 `fork` / `open` / `resize`。

运行包由锁文件 `npm ci` 全量重建，285 个 `@deepseek-ai` 包版本一致。

## 兼容性与边界

包名、签名、`minSdk 24` / `targetSdk 28`、数据目录与会话格式不变，
支持从 0.32.3 及 0.33.0 直接覆盖安装，不调用付费模型。

需要注意：

- 运行包由 payload-v10 换成 payload-v11。升级时 App 会按分片修订号只下载
  **变化的那一片**，四个工具分片不会重下。
- **本版尚未经过完整真机覆盖安装验收。** 终端修复的分片内容已按上述方式验证，
  但「装上新版 → 运行包升级 → 终端可用」这条完整链路还需要在真机上走一遍。
