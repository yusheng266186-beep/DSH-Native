# 阶段一：稳定性与安全加固

本阶段先解决会直接导致用户丢任务、下载失败、敏感信息暴露或更新链路被篡改的问题，
不改变 `targetSdkVersion = 28`，也不直接更换现有签名证书。

## 已完成

- 前台服务持有并监管 Node 进程；Activity 重建不再结束任务，通知栏「停止」可直接终止受管进程。
- 修复服务探测错误使用固定 3080 端口的问题。
- 运行包清单使用 APK 内置 SHA-256 固定；清单、分片名称、目标、大小、摘要、哨兵和删除路径均校验。
- 下载使用 `.part` 断点续传、来源身份文件、2MiB 响应上限、严格 `Content-Range` 与原子提交。
- 更新失败时保留已有可用运行环境；所有待更新分片下载并校验后才开始解压。
- 首次下载前检查 ARM64、可用空间，并在移动网络下显示预计流量。
- App 更新包下载完成后核对版本、包名与当前安装签名。
- 常驻日志迁入 App 私有目录；诊断导出会隐藏会话恢复原文并再次脱敏，旧共享日志会被清理。
- 配置备份默认使用口令派生密钥与 AES-GCM 加密；旧明文 ZIP 仅保留恢复兼容，并标明风险。
- 分享导入支持单个/多个文件，限制 512MiB，清洗名称、避免覆盖并以临时文件原子提交。
- 文件删除不会跟随符号链接越界；运行时与工具链目录在文件浏览器中改为只读。
- 外部明文 HTTP 默认禁用，只允许 `localhost` 与 `127.0.0.1` 上的本机 DSH Web 服务。
- CI 增加 pull request 构建入口，第三方 Actions 固定到完整提交 SHA；新安全逻辑纳入纯 Java 回归测试与架构闸门。

## 验证

- 15 个纯 Java 测试程序，共 580 项断言。
- 资源 XML、无 Android 依赖纯逻辑层、无系统 `AlertDialog`、无源码 emoji 闸门。
- Git diff 空白错误检查与 Python 构建脚本语法检查。
- 完整 Android 编译、aapt2 清单检查与 APK 签名检查由 GitHub Actions 执行。

## 需要单独迁移的签名问题

仓库历史中的发布密钥已经公开，不能再作为强安全身份。直接换钥会让所有已安装用户无法覆盖升级，
并可能造成会话和密钥丢失，因此本阶段遵守项目红线，不做破坏性替换。

安全迁移应作为独立版本项目执行：确定 Android 7/8 用户兼容策略，准备新的私密签名身份，
提供加密配置导出与新包导入路径，并在真机覆盖安装矩阵验证后再切换发布渠道。

## 合并后真机检查

1. Android 7、9 和当前主力设备各完成一次首次安装与断点续传。
2. 启动长任务后旋转屏幕、切后台、返回 App，确认任务与端口不变。
3. 从通知栏停止，再启动 App，确认没有遗留 Node 进程。
4. 低空间和移动网络场景确认提示文案；错误口令、损坏备份、旧 ZIP 各恢复一次。
5. 单文件、多文件、同名文件与超大文件分享导入各验证一次。
