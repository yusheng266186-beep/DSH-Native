## 验证证据与其边界

| 层级 | 已有证据 | 不能据此推断 |
|---|---|---|
| 纯逻辑与脚本 | JVM、JS、HTTP 探测、发布与文档回归；以当前脚本输出为准 | 所有 Android UI 与设备差异已验证 |
| Android 构建 | build / release 工作流实际执行编译、DEX、资源、签名与 APK 检查 | 只凭编译即可确认真机操作体验 |
| 实际模型消费 | 固定快照 92 个 Command Code ID，加两个 DeepSeek 直连项；真实 Host 目录、适配器与离线 SDK 请求体验证 | 对账户可见性、未来新增 ID 或真实模型思考预算的在线保证 |
| 聊天框 | 实际 React 选择组件与会话 RPC，94 个模型 × 两种语言的 188 组选择验证 | 原生 Android 触摸布局、付费服务执行 max 的结果 |
| 内核消费 | 实际会话创建/刷盘/重开、独占发布、FUSE 降级、磁盘错误、Linux 锁、模拟 Android 入口和 Web profile 认证 | 手机 PTY ELF、相机/相册附件与全 ROM 行为 |
| 已有真机反馈 | 阶段四 B 清单于 2026-09-27 由用户确认验收；本轮之前用户已确认模型更新与思考选项出现 | 其余历史功能、所有页面深色/大字体、多机型矩阵全部通过 |
| 发布 | 每次正式发布核对既有签名、资产、摘要及下载路径 | 已自动完成用户手机覆盖安装 |

“未采集所有布局数据”和“从未做过任何真机验证”是不同结论。后者已不符合项目记录；前者仍需要按页面和设备逐项补充。

## 仍需验证或评估的事项

- 本次新内核在真机的终端 ELF、图片处理、初次/增量更新和恢复路径。
- 所有原生面板的深浅主题、横屏、平板、大字体及 API 24 起的设备差异。
- 各 ROM 锁屏、后台回收、通知权限拒绝后的任务体验。
- 服务商对强制 `max` 参数的真实响应；当前回归不使用付费提示词。
- 曾报告的主线程卡死仍需可复现证据与日志，不能把没有新记录写成已经修复。
- targetSdk 迁移需要可执行文件部署架构评估，不属于普通文档/功能修改。

每次新增验收证据应记录日期、版本、设备/环境、步骤与结果。旧研究或未验证的服务端端点不能直接转为产品能力声明。

## 维护规则

1. 用户入口维护两份 README；技术事实以源码和固定依赖为准。
2. 当前能力与验证边界维护本页；历史阶段只追加说明，不伪造重新验收。
3. 版本、payload、内核、摘要与模型快照表由脚本生成。
4. 修改后运行 `sync_project_metadata.py --docs-only`，再运行检查与适当回归。
5. 正式清单只由 `release.yml` / `release.sh` 在下载验证后更新。
