# 1.1 应用架构重构

<!-- dsh-doc-status:start -->
> 现行文档：按当前源码维护。 已发布 stable：**1.0.0**；源码：**1.1.0**；源码运行包：`payload-v14`；固定 DSH：`0.2.1-rc.3`（上游候选版）。[统一进度与验证边界](STATUS.md)。
<!-- dsh-doc-status:end -->

用户在 1.0 安装后报告主题切换卡死，并要求全面重构、清理旧残留、统一体验和提高启动速度。沿用不做真机/模拟器验证、完成后直接发布新版的约定。

## 目标和完成标准

1. **主题与界面状态**：移除主题触发 Activity 重建的旧机制；由独立 ThemeController 管理取消、文档代次和系统/网页主题来源，NativeTheme 原位更新既有控件。保持输入、光标、弹层、滚动和连接。
2. **构建期 Android 运行包**：将固定内核的兼容适配统一前移到构建阶段，生成可直接安装的 Android 运行包；清理手机启动时散落的模块遍历、字符串替换及重复修复。仍需动态设备路径的工具准备单独负责，按实际环境修订执行。
3. **资源安装与运行目录**：由独立资源安装器负责版本/清单、原子落盘和资源状态；启动协调器区分环境准备、启动进程、连接与首帧，避免同版已就绪环境被 App 版本或主题变化反复准备。
4. **生命周期和异步任务**：统一启动/重启互斥、结果代次和取消；UI 销毁不再留下旧启动回调。WebView 由单一会话模块管理，保留页面、连接与草稿，运行时操作使用服务监管的真实进程状态。
5. **职责与旧代码**：MainActivity 保留 Android 入口和界面组合，将环境、安装/更新、WebView、主题、诊断及设置调度迁入对应模块。删除已无生产调用的旧凭据写入和重复设置工具；保留用户数据所需的迁移入口。
6. **体验与验收**：原设置结构、原主题令牌、原生能力授权与文件编辑状态保持一致。验证主题连续切换、系统跟随、前后台、启动取消/重试、同版冷/热启动、更新恢复、模型与工具和全部新旧页面。用最终提交完整 Android CI、原签名与真实公开下载验收，再发布 1.1 正式版本。

包名、签名、历史、项目、附件、账号凭据及恢复日志不改变。固定内核/SDK 更新须有来源和兼容记录，不能通过放宽校验来实现“提速”。桌面及 API 边界回归不冒充手机实测。

## 实现和边界

- `ThemeController`、`ThemeSync`、`NativeTheme`：主题来源、80ms 合并、文档代次和弱引用颜色注册独立管理。删除主题触发的 `recreate()` 和旧 1.2 秒重建定时器；保留输入、光标、滚动、弹层及状态颜色。
- `AndroidRuntimePort`、`AttachmentPort`、`build_android_runtime.py`：19 项固定内核适配统一在构建时完成；每个适配检查锚点和幂等性，再对整条链执行第二遍一致性检查。`payload-v14` 包含 Pillow、完整设置/文件/语音/连接适配，手机启动不再遍历改写这些模块。固定内核仍为 0.2.1-rc.3，四个工具分片逐字节复用 v13。
- `AssetInstaller`：最终 APK 在打包时生成组件大小/摘要索引，资源按内容更新并原子替换。私有回执用于复用未变的大型组件；小脚本仍重新核对摘要。旧安装首次迁移按磁盘实际摘要确认，不用旧 App 版本号代替内容证明。中断/错误摘要不覆盖旧文件或回执。
- `archive-tar.cjs`、`unpack.js`：用共享流式解包器替换旧整包缓冲解析器，支持 GNU 与 PAX 扩展长路径，保留可执行位/符号链接，并按文件原子发布。APK 安装、运行包恢复及 CodeBuddy SDK 解包都走同一实现；不会把完整展开 tar 一次性放入 JS 内存。消费回归按 APK 固定清单逐片校验全部五个公开归档的大小/摘要，再使用实际 APK 解包器和哨兵验证，不再由桌面 tar 代劳。
- `RuntimePreparation`、`RuntimeLauncher`、`RuntimeChecks`、`ProcessRunner`：设备绝对路径、自检、进程环境与临时命令各自负责。工具准备按修订和工具目录变更执行；自检缓存按组件、分片及工作区确认。临时命令有超时和取消；实际 DSH 进程继续由 HarnessService 独占监管。
- `StartupCoordinator`：同步决定启动/重启是否受理，再进入共享运行目录锁和执行停机。旧启动回调按代次丢弃，销毁取消等待；运行包更新、回滚和配置恢复使用同一环境锁。运行任务/未知状态下仍保护旧内核，不强行停机升级。是否需替换内核按组件内容、固定清单和工作区判定，删除旧 coreAppVersion 门槛；单纯提升 App 版本不再使相同内核失效。
- `WebSession`、`ViewportState`：统一浏览器创建、设置、前后台和销毁。旋转/分屏直接更新现有 viewport，保持 480 窄屏下限，不再写 HTML 或重新加载页面。清理中的单个渲染器错误不会跳过后续销毁步骤。
- `SettingsNavigation`：统一网页设置、原生回退、设备面板的焦点交接与返回分类；请求去重按文档管理，旧页面回调不能弹出过期面板。设备能力继续由 WebSettingsHost 与现有专门面板承接。
- `AppLog`：有界后台诊断、持续轮转和统一脱敏。logcat 与私有磁盘都在入口脱敏；单行长度和排队数量有界；关闭界面后不能复活日志线程。删除未被调用的旧凭据写入/表单辅助方法、反射 API 16 权限路径及旧线程/安装实现，保留配置、凭据、项目与运行包恢复迁移。

MainActivity 仍负责 Android 回调和各专门模块的界面组合；本次重构没有宣称所有复杂性都消失。后续功能应进入对应模块，不再把资源改写、下载器、主题控制或命令等待塞回 Activity。

## 验收记录

- 旧 `onWebTheme` 的实际生产方法未通过“不得重建 Activity/WebView”的回归断言；替换后 14 项主题生产方法检查通过。
- 实际 DSH WebUI 和实际 Java 主题控制器联测 40 项通过：连续切换、系统跟随、隐藏/恢复、设置保留、草稿保留，以及手机/横屏/平板/分屏重排不导航。
- 新架构 48 项生产代码回归通过，覆盖资源中断、错误摘要、重试、组件复用、启动互斥/取消/代次、临时命令、设置交接和日志脱敏。实际 HTTP 下载 8 项通过；浏览器边界 7 项通过，含 100 次前后台/viewport 循环和故障清理。
- 从固定 v13 归档运行 **1.0 的实际 MainActivity 适配方法**，所得旧环境的 21 个组件均匹配新版兼容记录；支持已适配旧环境的离线升级/回滚，不在手机补写内核源码。未完成适配的旧包仍须正常下载更新，不能降低信任校验。
- 解包器 6 项测试通过（含 GNU/PAX、UTF-8、1/7/511/512/65536 字节分块、长链接、权限、截断、错误校验和、父级链接越界及真实 zstd 入口）。对公开归档用实际 APK 解包器展开后，62,961 个文件逐文件摘要一致、11 个链接目标一致，覆盖 5,818 个扩展长路径；整个实际归档的最大元数据缓冲为 696 bytes，另有流缓冲和解压器自身内存，不冒充手机峰值内存测量。
- 本地全套测试和 API 28/34 编译结果以最终提交复核为准。完整 Linux Android CI、公开运行包消费和发布后同签名下载校验仍待最终记录，未冒充已发布或真机通过。
- 按用户约定不做真机或模拟器验证，不发送付费模型提示词。手机首启实际秒数、ROM 回收和录音权限由用户安装后验证。
