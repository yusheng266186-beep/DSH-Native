0.40.0 在 APK 内置官方 `@tencent-ai/agent-sdk` 0.3.291 和它随附的 CodeBuddy CLI 2.176.0。手机直接运行，无需电脑或另外安装 Termux。现有 `CODEBUDDY_API_KEY` 继续从 DSH 凭据解析，不需要重新导入。

## 为什么改用 CLI

用户在 0.38.0 遇到服务端 400 / 11128。核对 beichen 固定提交 `b99ed431aa50cf9eea6a86fa4b3a188388a495ff` 后确认，它是 `.cn/v2` 的 Bearer + stream 调用，没有特殊渠道认证。相同密钥的简单请求正常，直接发送完整 DSH 请求仍被拒绝；把 DSH 系统提示词作为官方 SDK 的替代系统提示词也被拒绝。因此删去旧的额外产品/IDE 头并不足以解决问题。

当前使用官方 SDK 的标准 CLI 代理模式，不伪造客户端标识、不修改文本来规避渠道检查。CLI 使用自身的代理行为；DSH 负责界面、会话记录和工具权限。DSH 的组合系统人格不作为 CLI 的替代人格，普通对话上下文、工作区信息、文件引用、图片和历史工具结果交给 CLI。0.40.0 的传输投影省去此前 assistant 的 reasoning/thinking 块，减少把历史思考当普通文本重复发送；可见回复、用户文字、工具参数/结果和图片不变，DSH 存储的思考与会话记录不改写。辅助标题/压缩任务保留任务指令。该模式与直接 LLM API 的系统提示词语义不同。

SDK 的内置工具全部禁用，个人/项目设置源、额外 MCP 配置和 CLI 会话持久化也关闭。只通过 SDK MCP 公共接口公布当前 DSH 工具及原始 JSON Schema。完整工具请求返回 DSH 循环，由 DSH 执行并将结果带入下一次请求；CLI 不直接执行模型请求的文件修改或命令。目录仍是固定 CLI 元数据，不能宣称所有模型已获账号授权。max 是传给 SDK 的请求选项，实际接受方式由官方 CLI 与模型服务决定。

## 使用与检查

安装新版覆盖现有 App，然后在更新与维护重启内核。从新会话选择 CodeBuddy；原有项目覆盖会保留，必要时在项目模型设置里切换。现有 Key 可直接使用，也可在模型设置填写 Key。

“检测连接与模型”通过内置官方 CLI 发送一个短请求，可能使用少量额度；只证明所选模型的这次检查。模型目录刷新不发送生成提示词，界面明确标注其来源；导入成功也不冒充对话检查成功。

首次使用自动校验和展开内置 SDK。0.39.1 只打包官方 headless 传输需要的原始文件，移除桌面 WebUI、服务端包和 DSH 不使用的外部工具及其他平台程序；保留文件逐字节不改写，许可仍随包分发。归档约 7.5 MiB、展开约 51 MiB；首次准备建议至少保留约 200 MiB 空间供运行与私有缓存使用。升级保留旧展开目录，不删除可能仍被尚未重启的旧内核使用的文件。SDK 归档进入已签名 APK，构建使用固定 lockfile；App 核对大小、SHA-256 和 SDK/CLI 版本，使用既有受限 tar 解包器。后续直接复用已准备版本。Node 编译缓存位于受保护的 `.codebuddy-home/compile-cache`，减少重复解析脚本。收到完整工具请求或普通对话成功结束后，使用官方 Session API 提前启动一个全新进程并读取初始化模式元数据；不发送用户提示词，不产生模型生成请求。连接检查与辅助生成不预热新的空闲进程。下一步只在凭据、模型、强度、工具 Schema 与运行选项完全相同时领取，领取后只使用一次；10 秒未用、配置不匹配或准备失败即关闭。不同会话不共享已发送的上下文，失败准备不覆盖本次工具结果。取消与空闲超时会撤销实际请求；错误不包含密钥或请求正文。

SDK 私有状态位于 App 私有 `.codebuddy-home`，不能通过文件分享或外部编辑导出，也不进入诊断 ZIP。验证中未发现 Key 写入该目录；Key 通过私有 stdin 或 SDK 子进程环境传入，不进入命令行、普通日志、Git 或 Release。

## 缓存统计口径（0.40.2）

固定 CLI 2.176.0 默认通道的 stream-json message/result 中，`input_tokens` 是包含缓存的输入总量；虽然字段形状接近 Anthropic Usage，不能直接作为 DSH 的未缓存输入。SDK 的 `modelUsage` 则已把 `inputTokens` 归一化为未缓存值。普通成功结果优先累加其完整四桶记录；工具请求在收到 result 前交回 DSH，因此用总输入减缓存读写，保留所有已报告 token。新增 `totalTokens` 是不重叠的输入、输出、缓存读写之和。未报告的缓存字段在适配层保持缺省，不补造缓存零值。

这会同时修正原聊天面板分母与 TokenMeter 的请求侧上下文占用。例如本机合成服务返回总输入 1000、命中 900，旧面板会给出约 47.4%，新版实际内核/原百分比格式化器得到 90%。50 轮回放覆盖累计与重复结算，官方 SDK 的流式和工具返回分别验证。SDK 未改写，未改客户端头；测试端点只在测试进程使用官方公开的 base-URL 选项指向本机。

已有会话日志保留原始统计，新请求按新口径记录。旧累计中仍可能包含旧版本数据；不能把合成响应的 90% 当作真实账号命中率。两次相同合成输入也检查模型请求公共前缀，不改写已可用的官方代理提示词或聊天历史。服务端缓存规则由服务商决定，见 [DeepSeek 缓存说明](https://api-docs.deepseek.com/guides/kv_cache/)。

## 私人加密导入

1. 电脑执行 `node tools/export_codebuddy_connection.cjs /absolute/private/output`，默认只读取 `~/.codebuddy/settings.json` 的 `env.CODEBUDDY_API_KEY`。
2. 把私人 `CodeBuddy.dshconnection` 送到手机，另行保管 `连接口令.txt`。
3. 设置 → 模型 → 导入连接，选择文件并输入口令。

格式仍为 `DSH-CODEBUDDY-1`，使用随机 salt/IV、PBKDF2-SHA256 200000 次和 AES-256-GCM。网页在本机解密，经 `credentials/set` 保存密钥；公开配置只保存引用。导入使用真实内核 RPC，全局默认与项目默认保持一致，不清空其他服务商或已有项目覆盖。

## 本次验证边界

- 在独立临时工作区，用本机真实账号完成实际 DSH → 内置 CLI → DSH write → DSH read → 回复保存；普通 Node 和 Android 平台选择边界均通过，没有 11128。不是手机实测，也不代表全部模型、图片与长期会话均已实测。
- 0.39.1 精简包通过实际 DSH 写入、读回与回复保存；启动/初始化测试不发送提示词，macOS 主机冷启动约 0.75 秒、提前启动 1 秒后约 2 毫秒。它衡量初始化开销，不是手机首字或端到端延迟保证。官方进程内 server 公共入口在隔离进程能完成短对话，工具事件输出与现有传输不同，尚未整合到生产路径，不能据此宣传已经原生直连。
- 自动测试使用合成凭据和 SDK 协议替身，覆盖流式去重、原工具 Schema、工具返回、取消、期限、错误脱敏、归档拒绝、精简体积上限、预热单次领取/凭据与模型隔离/取消和官方 CLI 的 Android 平台启动；不发送生成提示词。
- 按用户要求不做真机验证，由用户安装新版后验证小米手机环境。

官方接口与使用语义见 [Agent SDK](https://www.codebuddy.cn/docs/cli/sdk)、[自定义工具](https://www.codebuddy.cn/docs/cli/sdk-custom-tools)、[身份与认证](https://www.codebuddy.cn/docs/cli/iam)。官方 SDK/CLI 的 MIT 许可随归档保留。

## 旧服务商清理

CommandCode 面板、默认配置和旧凭据引用已移除。启动迁移仅处理 DSH 自有配置，保留其他服务商、账号授权、项目和历史；不重新导入共享原始文件里的旧密钥。托管 CodeBuddy 显示名更新为 CodeBuddy CLI，自定义服务地址保留。

## 1.0 候选的对话验收

完整错误结果同时读取 SDK 的 result 与 errors 数组，分别呈现认证、模型权限、限流、额度、上下文超限、渠道拒绝和网络失败；不把原始错误正文传给界面或日志。模型中心检查使用固定 failureCode 映射，不因目录可见而宣称对话授权。一个工具批次先完整校验，再交给 DSH，拒绝混合未知工具时不会先交出部分批次。

`codebuddy-conversation-consumer.mjs` 使用未修改的固定官方 SDK、本机合成服务、真实 DSH ToolRuntime 与 LocalFileSystem，完成写文件、读回、后续回复、60 条历史、取消后重发、压缩附加指令和 PNG 输入传输。它证明传输及工具消费，不证明服务商全模型授权、视觉回答或摘要质量。SDK 自身的重试规则未改写；生命周期恢复和取消不会由适配层重发用户聊天。

## 性能记录与缓存

普通对话结束写入 `[dsh-perf] codebuddy`，仅包含 setup/submitted/first/total 毫秒、是否领取预热与固定结果类型。first 是首段实际文本/思考或完整工具请求，不是单纯 socket 打开；所有时间从本次适配调用开始累计。连接检查/标题/压缩等辅助任务不输出该行，避免破坏检查协议。数据不含提示词、密钥、模型名或工具参数。

SDK 预热仍最多一个全新会话、10 秒有效、不发送模型请求。后台设置状态推送暂停，前台恢复补发。私有 compile-cache 的过期普通字节码可重新生成，按 7 天清理，遍历有界且不跟随符号链接。SDK 运行文件与未知使用状态的旧展开目录不自动删除；它们不能冒充普通缓存处理。
