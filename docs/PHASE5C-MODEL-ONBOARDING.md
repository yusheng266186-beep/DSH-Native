## 已完成

### 1. 模型中心

- 设置首页的“账号与模型”升级为“模型中心”。
- 支持 Command Code 与 DSH 内置的 DeepSeek 官方路由，明确显示当前服务商、模型和思考强度。
- 模型通过可搜索列表选择，不再要求用户记忆或手工猜测模型 ID。
- Command Code 模型来自当前 `settings.yaml` 中已经过能力声明的清单；DeepSeek 官方路由提供 `deepseek-v4-flash` 与 `deepseek-v4-pro`。
- 模型配置只写入 `agent-default-model` 顶层块，不用全局正则误改相邻模型条目。
- 密钥使用 YAML 引号和控制字符校验，仍只保存在 `.credentials.yaml`，不会进入日志、项目目录或模型配置文件。

DSH 官方文档说明：设置会在下一次请求时重新读取，而已经发送过请求的会话保留日志中记录的模型。因此保存配置不再强制重启或中断正在执行的任务；新模型用于新会话。

### 2. 服务商检测

- “检测连接与模型”只发起经过认证的 `GET /models` 请求，不发送提示词，不产生模型生成调用。
- Command Code 使用官方 Provider API 的 `/provider/v1/models`；DeepSeek 使用官方 `/models`。
- 对成功、密钥拒绝、限流、端点变化、服务异常和不可识别响应分别给出可操作说明。
- 成功后还会核对当前选择的模型是否存在于服务商实时列表，避免“密钥正确但模型已下线”的静默失败。
- 日志只记录服务商、HTTP 状态和模型数量，不记录请求头、密钥或响应正文。

参考资料（2026-09-28 核对）：

- Command Code Provider API：<https://commandcode.ai/docs/provider>
- DeepSeek Lists Models：<https://api-docs.deepseek.com/api/list-models/>
- DSH Providers：<https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/providers.md>

### 3. 项目级模型配置

- 全局默认模型之外，每个命名项目和默认工作区都可单独覆盖服务商、模型与思考强度。
- “项目与工作区”的每一行新增“模型”入口；未覆盖的项目明确跟随全局默认。
- 切换项目前先应用该项目的有效配置；写入失败则停止切换，不启动配置不一致的 agent。
- 项目映射保存为 App 私有目录中的 `.dsh/.native-project-models`，采用带版本头、UTF-8 十六进制字段和数量上限的可恢复格式。
- 项目映射随现有加密配置备份一起导出和恢复；旧备份没有该文件时仍可正常恢复。
- 配置文件使用同目录临时文件、同步落盘与重命名提交；失败时保留旧文件或可恢复备份。

### 4. 首次使用闭环

- 新安装仍先解释约 117 MiB 下载、空间与权限，再开始准备环境。
- 环境就绪后自动打开真正可操作的模型中心，而不是把用户丢到一个自由输入表单。
- 下载、进程或页面加载中断时，首次模型配置会在下次成功进入 DSH 后继续。
- 用户可以“稍后设置”；保存或明确跳过后不再重复打扰。
- 已存在 `.dsh` 的升级用户不会被补弹首次向导，原密钥、模型、项目和会话保持不变。

## 边界与未完成

- 实时 `/models` 只用于检查可用性，不自动把未知模型写进配置。模型列表接口通常不提供图片输入、上下文长度和思考等级等完整能力；自动导入会让图片在发送前被错误准入或拒绝。
- 已经发送过请求的会话继续使用它自己记录的模型；这是 DSH 的会话语义，不强行重写历史。
- 本阶段不增加自定义 Base URL 或任意请求头编辑器。此类功能涉及 SSRF、明文 HTTP 和敏感请求头边界，需单独设计。
- 服务商端点、模型 ID 或套餐权限仍可能变化；检测会明确失败，但不能替代服务商自身状态页。
- 项目模型是“新会话默认值”，不是按任务自动路由；自动路由属于后续产品取舍。

## 真机验收

1. 从 0.28.0 候选覆盖安装，确认显示 0.29.0，原项目、会话、密钥、文件回收站和任务历史保留。
2. 打开“工具与设置 → 模型中心”，在 Command Code 与 DeepSeek 官方之间切换；确认密钥字段保持、模型列表随服务商变化。
3. 用有效密钥执行检测，确认显示模型数量且当前模型可用；用错误密钥确认明确提示被拒绝，日志中不得出现密钥。
4. 搜索并选择模型，切换 `off / low / medium / high / xhigh / max`，保存后不应强制重启或中断当前任务；新建会话确认使用新模型。
5. 新建两个项目，为它们配置不同模型；来回切换并各自新建会话，确认模型不串项目。
6. 把其中一个项目改为“跟随全局”，修改全局默认后再次切入，确认它随全局变化，另一个覆盖项目保持不变。
7. 导出加密配置备份，再修改项目模型并恢复，确认全局模型、项目覆盖和密钥一同恢复。
8. 清除 App 数据模拟新安装：下载完成后应自动进入模型中心；在中途强制停止后重开仍会继续。选择“稍后设置”后再次启动不应重复弹出。
9. 在系统深色、大字体、横屏下检查模型中心、搜索列表和六档思考强度，按钮不得压扁或越界。
