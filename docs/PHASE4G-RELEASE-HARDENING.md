## 原始阶段记录

本阶段基于阶段四 E 的状态/设置修复和阶段四 F 的动效交互升级，针对发布候选做静态审计、生命周期修复与回归测试。目标是发布稳定版 0.26.3，不改变签名、数据路径、运行包或 targetSdk。

## 已修复

### 1. Activity 重建后的线程与界面泄漏

DSH 网页主题与原生主题不一致时会调用 `recreate()`。旧实现每次重建都会新建一条主线程看门狗和一条日志消费者线程，两者永久等待且通过 Runnable 持有旧 Activity；静态 `DshUi.LogSink` 也没有解除。多次切换主题后会累积线程、WebView 和整棵旧视图树。

修复后：

- `WorkerRegistry` 统一登记长期线程，`onDestroy()` 一次停止并中断。
- 日志入口按实例解除，旧 Activity 不会误清除新 Activity 的接线。
- WebView 停止加载、解除客户端、移出父容器并销毁。
- 文件选择回调收到取消结果，退出确认框与持续任务面板正确收尾。
- 销毁后到达的启动结果会检查 Activity/WebView 是否仍可用，不再访问已销毁 WebView。

### 2. 崩溃处理器重复套接

旧实现每次 `onCreate()` 都把一个匿名未捕获异常处理器套在当前处理器外层。Activity 重建后形成不断增长的代理链，每一层都持有对应 Activity，一次崩溃还会被重复写入。

`CrashReporter` 现在是无 Android 依赖的进程级处理器。重复安装只更新输出文件，处理器实例与系统代理链保持一层。

### 3. 密钥输入框 Autofill

API 密钥输入框虽使用密码类型，但部分 ROM/输入法仍会把它识别为登录凭据。Android 8.0 及以上现在显式设置 `IMPORTANT_FOR_AUTOFILL_NO`；旧系统保持原有密码遮罩行为。

### 4. Provider 未知路径回退

旧 `UpdateProvider.openFile()` 只区分“分享前缀”和“其他”，任何未知路径都会回退为 `update.apk`。这会掩盖 URI 拼写错误，也让一次性授权的语义过宽。

`ProviderRoute` 现在只接受：

- `content://dev.dsh.native.updates/update.apk`
- `content://dev.dsh.native.updates/f/<编码后的白名单文件>`

其余 authority 或路径明确拒绝；分享文件仍需经过规范路径、常规文件和敏感文件名校验。

### 5. 安装器未打开却显示成功

缺少“安装未知应用”权限或系统没有可用安装器时，旧流程会先把维护任务标成成功，再返回权限页或错误提示。现在安装启动返回明确结果，只有安装器已真正拉起才显示“等待确认”；权限与失败状态分别给出可恢复提示。

## 自动验证

- 原有纯逻辑、JavaScript 引擎模拟和阶段四 A 至 F 接线回归全部保留。
- 新增 `CrashReporterTest`：验证重复安装不套接、崩溃只代理一次且能写入日志。
- 新增 `WorkerRegistryTest`：验证销毁会中断长期线程、停止后拒绝新线程。
- 新增 `ProviderRouteTest`：覆盖合法更新/分享 URI、错误 authority、相似路径、额外路径段和空目标。
- 新增发布加固接线检查：Autofill、静态日志解除、线程停止、WebView 销毁和安装结果判定。

## 真机验收重点

1. 从 0.26.0 或同签名测试包覆盖安装，设置页应显示 0.26.3，项目、会话和密钥保留。
2. 在 DSH 内切换浅色/深色数次并旋转屏幕，界面不应闪退、卡住或出现重复面板；运行日志不应出现多条看门狗启动记录同时活动。
3. 打开账号设置，聚焦 API 密钥输入框；系统密码管理器不应弹出保存或自动填充建议。
4. 清除“安装未知应用”权限后检查 App 更新，应进入权限页并显示“等待授权”，不得显示更新成功；授权后重试应打开系统安装器。
5. 验证通知栏空闲、运行、等待批准、任务完成和网络切换状态，运行时长持续增长且任务结束后不继续计时。
6. 侧边栏收起时点击 DSH 齿轮，应打开 DSH 设置；展开侧边栏后“App 工具”仍打开原生工具与设置。

## 剩余风险

- JVM 与 Android CI 可以证明逻辑、编译、打包、签名和接线，不能替代目标 ROM 的 Autofill、系统安装权限页、WebView 资源回收和动画观感验证。
- DSH 页面结构来自上游；工具入口与状态探针继续采用幂等注入和失败退路，但上游大幅改版时仍需重新验收。
