## 归档状态与后续变更

本阶段对应实现已进入主分支。以下验收步骤、测试数量和发布限制保留当时版本语境；当前完成范围与未验证项目统一见 [STATUS](STATUS.md)。

## 原始阶段记录

本阶段基于阶段五 C 的 `0.29.0` 候选继续，正式发布版本为 `0.30.0`（`versionCode 3000`）。目标是在阶段五功能合并前补上更新失败的恢复出口、可直接分享的诊断现场，并让原生界面和 WebUI 在小屏、横屏、平板、系统大字体与“减少动态效果”下保持可用。

包名 `dev.dsh.native`、发布签名、用户数据目录、payload-v9、minSdk 24 与 targetSdk 28 均不改变。`.dsh` 会话、凭据、项目文件和工作区不进入回滚快照，也不会在恢复时被覆盖。

## 已完成

### 1. 运行环境事务式回滚

- 运行包有变化时，先下载并验证全部新分片，再为将要变化的 `dsh` / `tools` 目录创建 tar.zst 快照，最后才开始解压和删除旧文件。
- 快照由 APK 内置的 `snapshot.js` 流式生成，不把整个运行目录读入内存；目录遍历不跟随符号链接，归档先写唯一临时文件，压缩完成后才启用。
- 快照记录包含创建时间、目标目录、归档大小、SHA-256 与更新前的分片修订号。记录格式、目标白名单、修订号、饱和空间计算均在纯逻辑层验证。
- 解压或删除任一步失败时，App 自动停止受管进程并恢复上一环境；恢复每个目录时先保留当前副本，快照解压或关键文件验证失败会立即把当前副本放回。
- 成功更新后，“更新与维护”保留一次“恢复上一运行环境”入口。手动恢复只回退 DSH 与工具链，完成后重启服务。
- 自动或手动恢复后暂缓后台重复更新，避免每次启动重新进入同一失败循环；用户点击“更新运行包”即解除暂缓并主动重试。
- 删除逻辑改走 `FileOps` 的规范路径、白名单和符号链接边界，不再使用会递归跟随链接的旧删除函数。

这里的“回滚”不是 APK 降级。Android 原地安装要求新包的 `versionCode` 不低于当前版本，而卸载后降级会清空 App 私有目录；为了保住会话和密钥，本阶段只回滚可独立替换的 DSH / 工具链运行环境，不提供破坏升级路径的 APK 降级按钮。

### 2. 可分享的诊断中心

- “导出诊断包”由单个文本升级为 ZIP，并在生成后直接打开系统分享面板。
- `summary.txt` 包含 App/通道、Android 与 ABI、屏幕像素与 dp、字体缩放、设备布局档位、WebView、运行包修订、空间占用、回滚状态、任务、WebSocket、网络、通知和当前维护任务。
- `launch-log-tail.txt` 只保留最近 512 KiB 日志并再次脱敏；`privacy.txt` 明确说明隐私边界。
- 诊断包不包含 `settings.yaml`、凭据文件、会话正文、附件或项目内容。会话恢复原始文本只报告“存在”，不写入正文。
- 共享存储不可写时回退到 App 缓存，并继续通过既有的只读 `UpdateProvider` 提供一次性 `content://` 授权。

### 3. 无障碍与大字体

- 原生按钮触摸目标统一提升到 48dp。
- 对话框标题和区块标题在支持的系统上标记为无障碍标题；异步状态统一使用 polite live region。
- 底部操作区不再无条件横向等分：三个操作在手机上纵向排列，四个以上始终纵向，两按钮在极窄屏或 1.55 倍以上字体时纵向排列，避免标签被压成无法区分的省略号。
- 纵向按钮允许两行文字，横向按钮继续单行省略；既避免大字体溢出，也不改变普通平板的紧凑布局。
- 已有任务进度的屏幕阅读器播报、系统动画缩放开关与触觉开关继续保留。

### 4. WebUI 与多设备适配

- 对话框宽高计算抽到纯逻辑 `DeviceLayout`，手机保留总计 24dp 横向安全空间，平板上限 720dp，高度不超过可用屏幕的 86%。
- WebUI 对话框内长操作文字允许安全换行；粗指针设备把非 switch 操作目标提升到 44 CSS px，避免再次压扁 DSH 自己的滑动开关。
- 注入样式响应 `prefers-reduced-motion`，关闭非必要动画与平滑滚动。
- 保留窄屏 480 CSS px 的 fit-to-width 策略、520px 设置弹窗纵向布局、横屏高度约束和 1440px 上限。
- 解压器的路径边界从字符串前缀改为“目标根 + 路径分隔符”，并拒绝已有父级符号链接，修复同名前缀目录与链接逃逸边界。

## 自动验证

- `PayloadRollbackTest`：23 项，覆盖目标白名单、归档名、修订号、严格记录解析、重复项、摘要和空间计算溢出。
- `DiagnosticReportTest`：8 项，覆盖结构、控制字符、长度上限与凭据脱敏。
- `DeviceLayoutTest`：13 项，覆盖手机/平板宽高、极窄屏、大字体、按钮数量和设备档位。
- `MobileLayoutTest` 增至 25 项，补充触摸目标、switch 排除、减少动态效果和长操作文字。
- `OperationGateTest` 增至 13 项，确保恢复任务与更新任务使用不同互斥操作。
- Node 真实文件模拟覆盖：快照压缩、恢复、可执行位、长文件名、符号链接，以及恶意 `../` 归档不得越界。
- 连同阶段一至五 C 的既有回归共 `1036` 项纯逻辑断言，另有 17 项 WebUI 入口 DOM 模拟、11 项状态探针 fetch 模拟、7 项状态 DOM 模拟和阶段接线闸门。
- Android 的 javac、aapt2、DEX、签名、清单、APK 产物及覆盖安装签名由 PR 与正式发布工作流验证。

## 风险与边界

- 更新前快照需要额外空间。预检按“新分片更新空间 + 旧目标未压缩大小 + 32 MiB 余量”保守计算；空间不足会在修改运行目录前停止。
- 当前 payload-v9 没有新修订时不会凭空创建快照，“恢复上一运行环境”保持禁用。这不是故障；下一次真实运行包更新成功后才会出现可恢复版本。
- 快照期间会停止 App 管理的 DSH 进程，避免边运行边复制造成不一致；更新本来就需要重启，因此不新增额外的任务保活承诺。
- 诊断包只能证明导出时的 App 观察结果，不能替代 OEM 通知权限页、系统 WebView 崩溃记录或服务商状态页。
- 平板、折叠屏、TalkBack 和各厂商大字体渲染仍需真机抽查；纯逻辑矩阵只能保证布局决策，不等于像素级真机截图。

## 真机验收

1. 从当前正式版 `0.26.3` 或任一阶段五候选直接覆盖安装 `0.30.0`，确认包名不变、系统没有签名冲突，会话、密钥、项目、任务历史、回收站与文件全部保留。
2. 打开“App 工具 → 更新与维护”，确认显示 `0.30.0`。payload-v9 未变化时，“恢复上一运行环境”应禁用并明确显示没有快照，不能伪装成可用。
3. 点击“更新运行包”，确认已是最新时不会停止服务或创建无意义快照；以后有真实分片更新时，更新成功后恢复按钮应启用。
4. 在存在快照时点“恢复上一运行环境”，确认二次说明明确“不动用户数据”，恢复后服务自动重启，设置页显示自动更新暂缓；再次手动更新可解除暂缓。
5. 打开“诊断与日志 → 导出诊断包”，确认系统分享面板出现；解压 ZIP，检查三个文本文件存在，搜索真实 API Key、token、会话正文和项目内容，均不得出现。
6. 分别在 320–400dp 小屏、横屏和 600dp 以上平板打开任务中心、日志、模型中心和文件浏览；三个以上底部操作在手机应纵向排列，平板普通字体下可横向排列。
7. 把系统字体调到最大，确认标题、说明、按钮可读且操作不重叠；开启 TalkBack，标题应按标题导航，异步状态变化应播报。
8. 在系统中关闭动画，再打开原生设置和 WebUI 弹窗，确认功能立即完成且无强制装饰动画；恢复动画后过渡正常。
9. 在浅色、深色、页面刷新、SPA 路由切换和横竖屏旋转后回归阶段四工具入口、阶段五任务中心、文件/会话、模型中心，入口不得重复或丢失。

## 发布结论

阶段五 D 与阶段五 A/B/C 一起进入 `0.30.0` 正式版。发布必须依次通过堆叠 PR 的 Android CI、合并后的发布工作流、旧正式版签名比对、APK 清单与 SHA-256 校验，以及直连和镜像下载验证；只有全部通过才更新 `latest.json`。
