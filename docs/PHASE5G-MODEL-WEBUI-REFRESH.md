## 原始阶段记录

本轮目标版本为 `0.31.3`，承接 `0.31.2` 的模型目录写入能力，解决“原生模型中心已经拉到上游模型，但 DSH WebUI 仍看不到、也没有更新模型列表入口”的问题。

## 根因

`0.31.2` 保存动作已经把 `/models` 返回的 ID 写入 `.dsh/settings.yaml`，但保存后只调用 `WebView.reload()`。Android App 复用的 DSH Node 进程可能已经在启动时建立 provider topology 和模型目录，页面重载并不会让该进程重新读取文件，因此 WebUI 继续显示旧目录。侧栏也没有一个能回到模型中心执行上游刷新并重新应用目录的入口。

## 修复

- 在 DSH 侧栏设置项旁边加入幂等的“更新模型列表 / Refresh models”入口。入口跟随侧栏展开状态参与正常布局，收起时移除，不覆盖 WebView，不新增 `JavascriptInterface`。
- 入口通过既有控制台消息标记打开原生模型中心；模型中心的“更新上游模型列表”按钮继续调用服务商 `GET /models`，只把成功返回的模型 ID 写入受支持的 provider catalog。
- 保存目录后，空闲状态下安全停止并重新启动 DSH runtime，再加载 WebUI。这样 provider topology、模型选择器和默认模型从同一份最新配置构建。
- 运行中或等待批准的任务不会被重启打断：目录仍原子写入，通知用户任务结束/下次打开 WebUI 时应用；原有上游目录不会因失败请求被清空。
- 保留中英文、页面刷新、SPA 重绘、横竖屏和深浅主题兼容；重复注入不会产生重复入口。

## 真机验收

1. 从 `0.31.2` 同签名覆盖安装 `0.31.3`，确认会话、密钥、项目、任务历史和工作区仍在。
2. 展开 DSH 侧栏，确认出现“更新模型列表”；收起侧栏后该入口消失且不挡页面；重新展开只出现一个。
3. 点击“更新模型列表”，在模型中心选择 Command Code 或 DeepSeek 官方直连，点击“更新上游模型列表”，确认列表来自当前 API key 的实时 `/models` 响应。
4. 选择一个旧静态预设中不存在的模型并保存。无运行任务时，页面会短暂重建 DSH runtime；回到 WebUI 的模型选择器，确认新模型可见且默认选择一致。
5. 在任务运行期间重复保存目录，确认任务不中断；任务结束后重新打开 WebUI，确认目录已经应用。
6. 刷新页面、旋转屏幕、切换深浅主题和中英文，确认两个入口不重复、不丢失、不遮挡内容。

## 风险与边界

- 空闲保存会重启本地 DSH 服务，可能丢失未提交的 WebUI 草稿；任务运行中明确不重启。
- 上游 `/models` 只提供模型 ID 时，图片/推理标签仍按安全的未知能力处理，不凭空宣称能力。
- 不改变包名、签名、用户目录、payload-v9、minSdk/targetSdk，不迁移密钥，不直接合并 main。
