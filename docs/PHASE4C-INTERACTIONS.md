## 原始阶段记录

阶段四 C 在阶段四 B 已完成真机验收的基线上，收敛“点了是否生效”、

## 已完成

### 1. 统一面板动效

- 所有经 `DshUi` 创建的原生面板共用同一窗口动效：进入
  180 ms，退出 140 ms。
- 只使用透明度与纵向位移，不做缩放、弹性或强制延时，
  避免大字体和横竖屏下出现重新布局。
- 系统“动画程序时长缩放”为 0 时不安装装饰性按钮动效，
  对话框动效也会直接关闭。

### 2. 按钮按压、忙碌与结果反馈

- `DshUi.button` 统一提供 70 ms 轻微按压和 110 ms 复位反馈；
  不触发布局。
- 网络检测、Command Code 刷新、配置导出、插件安装、文件保存以及
  App/运行包更新，均保留原有忙碌态，完成后再显示 720 ms 的成功或
  失败结果。
- 延时复位使用代次校验，旧任务的回调不会在新任务开始后误恢复按钮。
- 状态改变会主动发出无障碍播报，中英文结果文案同步补齐。

### 3. 分享导入显式进度

- 从其他 App 分享单个或多个文件/文本时，用持续面板显示
  `已处理 / 总数`，而不再只显示短暂 Toast。
- 全部成功、部分成功和全部失败分别用成功、警示和错误语义色收尾；
  部分成功时仍保留已安全落盘的文件。
- 结果可见后才继续询问“是否用分享内容创建任务”，避免两个面板竞争。

### 4. 分享任务提交状态

- 提交到当前 DSH 会话时显示不确定进度，并消费现有安全的
  Web 控制台标记确认“已提交”、“已预填”或“未找到编辑器”。
- 5 秒未收到结果时明确提示用户检查输入框，不会无限显示“正在提交”。
- 超时回调也使用代次校验，不会关闭后来的新任务反馈。
- 仍沿用阶段四 A 的单向控制台标记，没有新增高风险 `JavascriptInterface`。

### 5. 项目切换进度不再被遮挡

- 点击切换后立即进入忙碌态；若当前有任务，取消确认会完整恢复按钮。
- 确认切换后先收起“项目与工作区”面板，再显示
  “正在切换到「项目」”的开屏进度，不再被原对话框盖住。

## 真机验收

1. 在已安装的同签名版本上覆盖安装测试 APK；确认系统不要求卸载，
   账号、会话、API 配置、工作区和命名项目全部保留。
2. 打开、关闭“工具与设置”及文件、日志、插件、网络等原生面板；
   进入应约 180 ms，退出应约 140 ms，无闪烁或布局跳动。
3. 在系统开启动画时点按多个主/次按钮；应有轻微按压反馈，松手立即复位，
   文字和布局不应抖动。
4. 将开发者选项的“动画程序时长缩放”设为关闭，重新打开 App；
   面板和按钮不应强制播放装饰动效，所有操作仍可完成。
5. 分享 3 个不同大小的文件到 DSH；进度应从 `0 / 3` 逐项到 `3 / 3`，
   完成后再出现“用分享内容创建任务”确认。
6. 分享一个已失效或无权读取的 URI，同时带一段可保存文本；应显示
   “已保存 1 项，失败 1 项”，已保存文本不得被删除。
7. 在上一步的确认中选“创建任务”；应持续显示提交中，然后明确收到
   已提交、已预填或失败之一，不应无限转圈。
8. 在 DSH 界面重载或输入框尚未就绪时提交分享任务；5 秒无确认时
   应提示检查输入框，已导入文件仍保留。
9. 在没有运行任务时切换命名项目；项目面板应先关闭，开屏应显示准确项目名，
   服务就绪后进入对应工作区。
10. 在任务运行中切换项目；先选取消，确认按钮恢复可点，且当前项目不变；
    再选“切换并重启”，原面板不得遮住切换进度。
11. 分别运行网络检测、Command Code 刷新、配置导出和一次故意失败的文件保存；
    按钮应依次显示忙碌、结果、默认文案，并且不能在忙碌时重复提交。
12. 在浅色/深色、中文/英文、系统最大字体和横/竖屏下重复上述核心步骤；
    状态色需清晰，文案不应裁切，TalkBack 应能读出任务结果。

## 暂未完成与风险

- 动效观感、系统动画缩放、TalkBack 播报、输入法/横竖屏与不同 ROM 的窗口行为
  必须用目标真机验收，自动测试无法代替。
- 分享任务的“已提交”仍依赖当前 WebUI 的 DOM 结构和现有控制台回执；
  上游改变编辑器结构时会在 5 秒后降级为人工检查，不会误报成功。
- 同一 Activity 中极快地连续发入多个系统分享意图时，导入写盘仍由
  全局锁串行保护；需要在目标 ROM 上确认系统不会叠加多个进度窗口。
- 没有提升稳定版、修改稳定/测试更新清单、合并 `main` 或发布 Release；
  真机验收后再决定后续发布动作。
