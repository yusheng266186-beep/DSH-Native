# 阶段四 E：状态栏与折叠设置入口修复

## 目标

针对 0.26.0 真机反馈，仅收敛两个阻塞验收的问题：

1. 无任务时通知长期显示“状态未知”，运行时长和结束提醒因此不可靠；
2. 侧边栏收起时，唯一的齿轮可能打开 App 工具，而不是 DSH 自己的设置。

本轮不把新的动效方案混入验收，避免同时改变状态、导航和视觉反馈后无法定位回归。

## 根因与修复

### 通知状态

- DSH 真机请求使用 `api/session/list`，旧探针只匹配带前导斜杠的
  `/api/session/list`，因此没有捕获和重放真实会话列表。
- 既有 Java 解析器支持 `[dsh-dom]` 状态，但页面脚本从未产生该信号，第二证据源实际不存在。
- 修复后同时使用两份证据：会话列表为权威来源；页面上可见的“停止生成 / 发送消息 /
  等待审批”作为独立兜底。全部匹配均要求精确文案且控件可见，避免对话正文误触发。
- 无证据的短暂加载态显示“同步中”，不再显示容易被理解成故障的“状态未知”。

| 场景 | 常驻通知 | 计时 / 提醒 |
| --- | --- | --- |
| 页面加载中 | 同步中 | 不计时、不提醒 |
| 没有任务 | 空闲；正文“当前没有任务在运行” | 不计时 |
| 任务执行 | 运行中 | Android 系统计时器逐秒显示运行时间 |
| 等待用户批准 | 等待批准 | 继续计时，并在首次进入时提醒 |
| 后台任务结束 | 空闲 | 任务超过 10 秒且 App 在后台时发送完成提醒 |
| 网络不可用 | 保留任务态并在正文提示网络异常 | 网络恢复后继续同步 |

### 折叠侧栏设置

- 旧实现用按钮宽度 `> 44px` 判断侧栏已经展开，真机布局中的折叠控件可能越过该阈值。
- 新实现优先识别 DSH 自身的 `rail / railRow` 折叠语义和可见设置文字，宽度仅作最后兜底。
- 侧栏折叠时不再仅给克隆行设置 `hidden`，而是直接从 DOM 移除原生入口；因此唯一留下的
  齿轮必定是 DSH 原始按钮。重新展开后，MutationObserver 会幂等恢复“App 工具”文字入口。

## 版本与更新通道

- 验收 APK 使用 `versionName 0.26.1`、`versionCode 2601`，可与两个 0.26.0 包明确区分。
- “测试版 / 稳定版”是保存在应用数据里的更新检查通道，覆盖安装不会重置；它不代表当前
  APK 本身。设置说明和运行日志已明确显示“当前安装包”版本。
- PR 构建允许源码使用严格高于已发布清单的下一版本；main 构建仍要求发布清单一致。

## 自动验证

- 774 项纯 Java 逻辑断言；
- 17 项 WebUI 工具入口 DOM 模拟，其中 48px 折叠控件复现旧误判；
- 11 项会话探针 fetch 模拟，覆盖相对 / 绝对地址、响应结构和未知响应不误报空闲；
- 7 项状态 DOM 模拟，覆盖空闲、运行、待批准、无依据、去重和重复注入；
- 构建期继续检查无新增 `JavascriptInterface`、无覆盖 WebView 的悬浮入口、无系统
  `AlertDialog`、纯逻辑层无 Android 依赖。

## 真机验收

1. 覆盖安装后，在 App 的“更新与维护”或导出的运行日志确认版本为 `0.26.1`。
2. 不启动任务，等待页面稳定 5 秒：通知应为“空闲 / 当前没有任务在运行”。
3. 发起一个超过 10 秒的任务并切到后台：通知应为“运行中”，系统计时器逐秒增加。
4. 任务结束后：常驻通知回到“空闲”；App 在后台时另收到“任务已完成”提醒。
5. 触发一次权限批准：通知显示“等待批准”，点开可返回 App 处理；批准后恢复运行或空闲。
6. 收起侧边栏后点击唯一齿轮：必须打开 DSH 设置。展开侧边栏后，“App 工具”和“设置”
   应为两个独立入口；反复收起 / 展开和刷新页面不得出现重复入口。

## 当前边界

- 页面加载、SPA 重绘或网络恢复期间可能短暂显示“同步中”，这是过渡态，不是任务状态。
- 完成提醒受 Android 通知权限、系统通知渠道和后台限制影响；若状态已正确切换但没有声音，
  需同时检查系统中的 DSH Native“任务完成”通知渠道。
- 本轮只交付 PR 验收包，不直接合并 main，也不更新稳定通道清单。
